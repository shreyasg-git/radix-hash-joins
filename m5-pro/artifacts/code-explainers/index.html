Code explainers

One page for each program in m5-pro/src. Each page says what is in the file, what each block takes in and gives back, and what the program does. They are in the order of the experiments.

scan_benchmark.cExperiment 1. Reads memory at different gaps to show how this Mac's cache behaves. No join. hash_join.cExperiment 2. The simple hash join. The baseline. radix_partition.cExperiment 3. The cost of splitting a table into groups, with 1, 2 or 3 passes. radix_join.cExperiment 4. The radix join against the simple join. parallel_join.cExperiment 5. Both joins on 1, 2 and 4 threads. bucket_sweep.cExperiment 6. How many buckets, and which hash function?

Words used on these pages

WordWhat it means
JoinPairing up the rows of two tables whose key is equal.
Hash functionA recipe that turns a key into a scrambled number. Used to pick a bucket.
BucketOne slot of the lookup structure. Rows whose scrambled key lands on the same slot form a chain.
Build, probeBuild: put every left row into the lookup structure. Probe: for each right row, look for matching left rows.
CacheA small, fast memory next to each core that holds copies of recently used data. On this M5: 128 KB closest to the core (L1) and 16 MB next (L2).
Cache lineThe chunk the cache copies in at one time. 128 bytes on this Mac.
PageThe chunk the operating system uses to map memory addresses. 16 KB on this Mac.
PartitionOne of the groups a table is split into, by the low bits of the scrambled key.
PassOne trip over all the data. Radix partitioning can split the bits over several passes.
ChecksumOne number made by adding up a fingerprint of every result pair. Two runs that find the same pairs get the same number, whatever the order.
Warm-up runA run that is done first and not recorded, so the first-run slowness is not in the results.
ThreadOne line of work that runs on its own core.
Nested loopThe slow join that compares every left row with every right row. Used in tests as the answer to compare against.
