radix_partition.c

Experiment 3: how much does one partitioning pass cost? File: m5-pro/src/radix_partition.c, 249 lines. It uses shared helpers from m5-pro/include/common.h.

The short version. Partitioning means sorting rows into groups by the low bits of their scrambled key, without sorting inside each group. This program does only that, with no join. It measures two things:

  1. How the time per row changes as the number of groups grows (from 1 group up to 220 groups by default).
  2. Whether splitting the same total number of bits over 2 or 3 passes is faster than doing it in 1 pass. One big pass writes to many places at once, and that can overload the processor's small caches. More passes keep each pass small, but read and write all the data again.

Page size on the Mac. The header describes a second experiment factor: 4 KiB pages versus 2 MiB "huge" pages, which only works on Linux. On macOS the program cannot choose a page size, so it uses the default and runs one page mode only. The CSV column page_mode says default.

Pieces from common.h this file uses

  • radix_pass (lines 257–285): does one pass. Sweep 1 (histogram) counts how many rows go to each new sub-group. A running total turns counts into start positions. Sweep 2 (scatter) copies each row into the next free slot of its sub-group. It returns the time of each sweep. The running total is counted in the scatter time.
  • split_bits (237–239): splits the total bits over the passes as evenly as possible. 7 bits in 2 passes becomes 4 and 3.
  • radix_of (232–234): the group number of a key: (mix(key) >> shift) masked to the pass's bits.
  • allocate_touched, generate, pair_hash, shuffle_order, counters_* (empty on the M5), steal_ms (-1 on macOS), pin_to_cpu, parse_number, parse_list, open_in, make_results_directory, write_common_environment.

partition lines 41–66

Input
The buffers, the row count, total_bits, passes, arrays to fill with per-pass times and counter readings, and the counters.
Returns
A Partitioned.
What
Starts with one group holding all rows. For each pass it takes the next group of bits (highest first), runs radix_pass over every existing group, records the histogram and scatter times, and swaps the roles of the two work buffers. The input is never changed.
With 0 bits and 1 pass there is one group, so the pass is a plain copy of the table. That gives a baseline: the cost of just reading and writing every row once.
This is the same loop as partition_all in radix_join.c, with the per-pass timing added.

Correctness checks lines 68–104

What
  • compare_records: orders records by key, then row_id.
  • check_partitioned: returns 1 only if all of these hold. (1) The first boundary is 0 and the last is the row count, and boundaries never go backwards. (2) Every row in group c has group number c. (3) The sum of pair_hash(key, row_id) over the input equals the sum over the output, so no row was lost or invented. (4) If asked to compare exactly, it sorts copies of the input and output and compares them byte by byte.

self_test lines 121–144

What
Tries 7 table sizes: 0, 1, 2, 37, 1,000, 4,096 and 100,003 rows. Keys include duplicates and the largest key (every 7th row gets 4,294,967,295; the others get random keys). For 1, 2 and 3 passes it tries every bit count from the lowest allowed (0 for 1 pass, otherwise the pass count) up to 12. That is 13 + 11 + 10 = 34 settings per size, 34 × 7 = 238 cases. Each case runs check_partitioned with the exact comparison on.

main lines 148–249

Usage
radix_partition --test, or radix_partition OUTPUT_DIRECTORY [--rows N] [--repeats R] [--max-bits B] [--passes 1,2,3] [--pages 4k,2m] [--seed S].
Defaults
16,777,216 rows (224), 15 repeats, up to 20 bits, passes 1, 2 and 3, seed 42.
Steps
  1. Creates a new results folder (fails if it exists). Writes environment.txt and the timings.csv header.
  2. For each page mode (only one on the Mac): allocates the buffers, and fills input with the left table from generate (the same data as the simple join, seed 42). The right table is made and thrown away.
  3. Lists every setting: for each pass count, every bit count from its lowest allowed value up to max_bits.
  4. Runs repeats + 1 rounds. In every round each setting runs once, in a newly shuffled order.
  5. Round 0 is the warm-up. It is the only round whose output is checked (with check_partitioned, without the exact comparison) and it is not recorded. The recorded rounds 1 to 15 are not checked.
  6. For each recorded run it writes one CSV row per pass.
Output
timings.csv columns: page_mode, rows, passes, total_bits, pass, pass_bits, clusters_after_pass, run, position, steal_ms, histogram_ms, scatter_ms, pass_ms, then the counter columns (empty on the M5). Also environment.txt.
